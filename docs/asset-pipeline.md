# Asset Pipeline: Phase 5 Prototype GLBs

## Provenance and generation

The four assets are original low-poly project geometry generated by
`tools/generate-assets.mjs` using Node built-ins only. No downloaded meshes,
third-party textures, Blender project, or additional runtime dependency is
used. From the repository root, regenerate with:

```powershell
node tools\generate-assets.mjs
```

The generator is deterministic and writes binary glTF 2.0 (`.glb`) with
embedded mesh data and static vertex colors. The materials are unlit, with
no runtime shadows or image textures. This is a deliberate prototype
substitute for the product design's future image-based baked lighting; it is
not production artwork or proof of intended lighting.

## Verified outputs

| File | Dimensions (m) | Named nodes | Triangles | Bytes |
|---|---:|---:|---:|---:|
| `public\assets\vehicles\sedan.glb` | 1.8 × 1.45 × 4.6 | 24 | 640 | 54,500 |
| `public\assets\vehicles\cuv.glb` | 1.8 × 1.62 × 4.35 | 24 | 640 | 54,508 |
| `public\assets\environments\roadside.glb` | 50 × 3 × 32 | 17 | 168 | 27,232 |
| `public\assets\environments\garage.glb` | 30 × 6 × 30 | 23 | 216 | 34,812 |

Counts were read from each GLB JSON chunk. Triangles equal the sum of each
primitive's index accessor count divided by three. File bytes are the committed
GLB lengths; no transport compression is assumed. The largest selected pair
is CUV + Garage (89,320 bytes); all selected pairs are below 90 kB before
HTTP compression and far below the 20 MB target. No texture dimensions or
texture transfer sizes apply because these assets contain no image textures.

Vehicle roots are centered on profile COM, use meters, +Y up and -Z forward,
and contain `Body`, `WheelFL`, `WheelFR`, `WheelRL`, `WheelRR`, `DriverEye`,
`MirrorRear`, `MirrorLeft`, `MirrorRight`, separate mirror surfaces, and basic
cockpit nodes. Environment GLBs include named floor/marking/wall groupings;
the garage has a separate `Ceiling` group. Physics colliders are explicit
TypeScript data in `src\world\colliders.ts`, not inferred from visual bounds.

## Runtime validation

`src\world\assets.ts` validates the GLB v2 container and asset contract before
returning a scene. Root transforms, vehicle body/cockpit bounds, eye
position/scale, and mirror anchor transforms are checked against explicit
profile metadata (0.02 m position tolerance); returned anchors are vehicle-root
relative. Environment floor bounds and transforms are checked against the
collider dimensions. Required named nodes and the garage ceiling group are
checked.
Malformed content fails with a typed `AssetLoadError` naming the failed
resource; no prototype-scene fallback is used.

The browser acceptance fixture loads each vehicle/environment combination
through Three.js `GLTFLoader` and renders it with a real WebGL2 renderer.
Loader/app tests cover cancellation, stale completion, retries, and exact
resource ownership. These checks do not replace manual cockpit, mirror,
clearance, or instructor review.

## Production-asset follow-up

Future release art should use documented original or appropriately licensed
models, metric units, one verified axis conversion, applied transforms,
COM-rooted vehicle geometry, useful cockpit sightlines, replaceable mirror
surfaces, and the approved environment grouping. Record actual dimensions,
anchors, triangle counts, draw calls, texture sizes, compressed transfer sizes,
provenance/license, and visual inspection results. Keep physics collider
metadata authoritative and independent from those visual exports.

Current assets meet the small prototype geometry/transfer budgets; they do not
meet or claim photorealistic art, image-based baked textures, validated
vehicle dimensions, clear mirror sightlines, environmental training routes,
or performance on a named reference PC.
